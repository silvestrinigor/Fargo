Suggested workflow
1. API request: POST /items/{guid}/lost
   - Validate that the item exists and can be marked as lost.
   - Register a loss operation with status Pending.
   - Return 202 Accepted with the operation ID.
2. Background service:
   - Picks up pending loss operations.
   - Processes the root item and its descendants.
   - Updates their statuses to Lost.
   - Creates the corresponding ItemEvent records.
   - Updates any relevant inventory aggregates.
   - Marks the operation as Completed or Failed.
3. Found request: POST /items/{guid}/found
   - Follows the same workflow, with a background operation restoring the eligible items.
